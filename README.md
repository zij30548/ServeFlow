# 智应 ServeFlow

面向复杂客服任务的多Agent协作系统。用户通过对话咨询，系统识别诉求、选择处理角色，按需查阅政策或读取业务工具，并展示处理结果。前端只有**对话**与**监控**两个工作界面。

当前项目已替换原TripPilot旅行应用。它是客服开发／演示项目，尚不具备直接公开给真实客户使用的完整生产安全条件。

## 功能

- 意图识别：LLM、本地模板相似度和关键词融合。
- 角色协作：通用客服、技术支持、账单售后、人工升级；复合问题支持主辅路由和结果合并。
- 知识检索：Chroma中的演示政策，按需查询改写、召回和重排。
- 对话记忆：Redis工作记忆、Chroma历史摘要与画像。
- 工具与Skills：明确工具白名单和参数校验；Skills提供处理规范。
- 监控：读取角色执行、工具、耗时及失败状态；技术执行成功率不等于回答准确率。
- 可选MySQL演示：10笔合成订单，支持核对拆单、权益和退款状态；只读、不执行真实退款。

模型负责理解和组织回复；政策资料与订单记录的职责分开。未知、错误和不确定结果应如实保留，不能将模型回复当作真实交易凭证。

## 本地运行

需要Python **3.12**、Node.js **20.19+或22.12+**、npm，以及可用的Redis。后端沿用Anthropic SDK，通过百炼官方Anthropic兼容接口调用千问；不是依赖Anthropic模型。

### 后端

```sh
cd backend
uv venv --python 3.12
uv pip install --python .venv/bin/python -r requirements.txt -r requirements-dev.txt
cp .env.example .env
```

在本机`.env`中填写：

- `ANTHROPIC_API_KEY`：百炼密钥，仅供服务端使用。
- `ANTHROPIC_BASE_URL`：北京地域官方Anthropic兼容地址，例如`https://dashscope.aliyuncs.com/apps/anthropic`；业务空间地址按控制台／官方说明填写。
- `ANTHROPIC_MODEL`：当前使用`qwen3.7-flash-2026-07-15`。
- `REDIS_URL`：自己的Redis连接。开发默认回环6379，也可配置私有Unix socket。
- `CHROMA_PERSIST_DIRECTORY`：私有本地数据目录；默认`./data/chroma`。

如果没有Redis实例，可在独立终端启动本机开发实例：

```sh
redis-server --bind 127.0.0.1 --port 6379
```

不要覆盖已有Redis配置或使用它清空其他应用的数据。后端启动：

```sh
.venv/bin/python -B run.py
```

后端仅监听`127.0.0.1:8816`。外部MCP默认关闭，不会启动时自动访问示例服务器。首次使用Chroma默认向量模型可能需要下载模型；后续本地向量化不代表付费Embedding调用。

### 前端

```sh
cd frontend
npm ci
npm run dev
```

打开 **http://127.0.0.1:5173/**。浏览器通过同源`/api/python`访问后端；开发代理默认指向回环8816。如需更改，使用可信服务端变量`SERVEFLOW_BACKEND_ORIGIN`，不要把密钥写入前端变量或运行时配置。

选择快捷问题只填写输入框，主动发送才进入模型链路。分类、Agent、检索改写／重排和后台记忆都可能产生模型费用；没有完整产品级硬额度，部署者须另行配置费用保护。

### 可选MySQL演示

```sh
cd backend
uv pip install --python .venv/bin/python -r requirements-demo.txt
```

按[示例配置](backend/.env.demo.example)创建**独立、空的演示库**及受限账号。初始化CLI仅读取当前进程环境，不会自动加载示例文件；在独立管理终端通过私有配置提供`SERVEFLOW_DEMO_ADMIN_MYSQL_URL`，不要把管理员连接交给Web进程，然后显式执行：

```sh
.venv/bin/python -B -m demo_business init
.venv/bin/python -B -m demo_business verify
```

初始化使用专用管理员连接；Web连接只授予该库SELECT。配置签名密钥文件及精确本机来源后，页面显示可折叠的演示数据入口。没有配置则功能关闭，不会自动建库。已有数据只验证，不覆盖或重置；DDL失败／提交结果不明时停止检查，不盲目重跑。

合成客户A／B及演示Cookie只用于本机样例，不能代替真实客户登录与业务授权。演示记录具有固定快照时间，不能声称查到实时商家物流。

## 量化评测的离线准备

[评测工具](backend/evaluation/benchmark.py)提供题集校验、文件哈希冻结、结果模板和离线计分，不读取`.env`、不连接数据库、不发送模型请求，也不会修改正式对话流程。

| 题集 | 开发集 | 验证集 | 范围 |
| --- | ---: | ---: | --- |
| 意图 | 24 | 36 | 12个核心类别，每类2道开发题、3道验证题 |
| 检索 | 12 | 12 | 每组6道可答、3道资料不足、3道未收录 |
| 业务任务 | 6 | 6 | 拆单、退款未知项、权益、跨客户边界、多轮及干扰指令 |

题目是按当前演示政策和合成订单编写的评测样本，不是模型训练数据，也不是独立人类盲测。开发与验证按场景族分组，验证题不用于调参；资料只有6篇，订单只有10笔，成绩不能代表真实企业的整体客服效果。验证集对编写者可见；精确去重也不能证明不存在语义相似。两组共享源政策和订单事实，例如`t05`与`t11`使用同一订单做无权限／有权限对照，不能称为订单事实也独立留出。

在`backend/`下执行：

```sh
.venv/bin/python -B -m evaluation.benchmark validate
.venv/bin/python -B -m evaluation.benchmark freeze \
  --output data/benchmarks/preparation-v1/manifest.json
.venv/bin/python -B -m evaluation.benchmark verify \
  --manifest data/benchmarks/preparation-v1/manifest.json
```

冻结清单只表示离线准备：授权与实际模型请求数均为0，完整真实请求尚未冻结。文件变化会导致核验失败，已有输出不能覆盖；新建目录不会获得模型额度。

以下命令创建**空的受控结果模板**，不会执行题目：

```sh
.venv/bin/python -B -m evaluation.benchmark template \
  --manifest data/benchmarks/preparation-v1/manifest.json \
  --suite intent --split development --arm fusion \
  --output data/benchmarks/preparation-v1/controlled-intent.json
.venv/bin/python -B -m evaluation.benchmark score \
  --manifest data/benchmarks/preparation-v1/manifest.json \
  --results data/benchmarks/preparation-v1/controlled-intent.json \
  --output data/benchmarks/preparation-v1/controlled-intent-report.json
```

空模板的题目全部标为未执行；受控结果和历史输出回放均不代表新的真实模型质量成绩。工具目前拒绝导入声称为实时模型验收的结果。输出默认私有权限，放在被Git忽略的`backend/data/`中；数据与结果契约见[样本目录](backend/evaluation/benchmark/)及[计分实现](backend/evaluation/benchmark_metrics.py)。

分类报告Accuracy和固定标签集的Macro-F1；检索报告Hit@1、Hit@3、MRR、前三条资料覆盖及未收录问题的误命中；完整任务保留实际角色与工具执行观测，先检查必需角色和工具是否出现，再逐项复核证据、覆盖、条件、缺失、状态、引用和权限，不能靠回答关键词自动判通过。工具名出现也不证明执行者具备权限，权限仍须单独核对。失败、取消、未知结果和未执行项保留在计划题分母；执行及必要观测均合格、但未复核的任务标为待核。耗时使用记录值的P50/P95，用量缺失记为未知。

对照计划是“仅LLM／三路融合”和“直接向量检索／改写召回重排”。当前任务题只准备当前版本基线，不能据此声称修复后提升。真实评测开始前仍须固定完整请求、执行顺序、持久发送台账和新一批明确调用额度。原有`/eval/run`不是本离线工具的执行入口，不应把其混合汇总通过率当作独立任务解决率。

### 首批意图开发集的执行准备

[专用执行工具](backend/evaluation/intent_trial.py)只针对24道意图开发题：每题取得一次LLM输出，同时计算原解析结果与当前三路融合结果，最多24次物理请求。融合固定使用本地字符n-gram与关键词，不接远程Embedding、RAG、角色回复或后台画像。两份决策共用一次模型观察与用量，属于消融对照，不是两套独立端到端A/B；模型请求耗时与本地融合耗时分别记录，不能据此宣称端到端延迟提升。

在`backend/`下准备，下面命令均不调用真实模型：

```sh
.venv/bin/python -B -m evaluation.intent_trial prepare \
  --offline-manifest data/benchmarks/preparation-v1/manifest.json
.venv/bin/python -B -m evaluation.intent_trial verify
.venv/bin/python -B -m evaluation.intent_trial status
.venv/bin/python -B -m evaluation.intent_trial report
```

工具通过真实SDK和内存传输捕获现有提示及请求字节，冻结模型、参数、逐题顺序、请求哈希、代码与依赖版本；可用`--prior-record`关联旧证据哈希，不读取或挪用旧额度。批次固定在`backend/data/benchmarks/intent-development-v1/`，原离线冻结件保持不变。准备时授权为0，只有获得本批明确授权并单独登记授权回执后，`run`才能发送；普通“开始准备”不会自动创建该回执。

发送前逐次检查版本、授权及已封存结果，再通过文件锁、不可覆盖claim和JSONL链持久占额。每题最多一次，重启或重复执行不补发；未完成尝试、计数损坏、鉴权、限流、网络、取消、超时或响应超限会停发。普通分类错误及生产解析失败保留后继续固定计划。默认不跟随重定向、不自动重试，8秒异步请求截止、64KiB请求和256KiB响应上限；响应逐块检查，资源清理另有有界等待，磁盘同步不属于硬实时截止保证。

原文只保留受限文本块及白名单模型／用量元数据，写入本机私有文件；不保存认证头、非成功错误正文或thinking内容。SDK详细日志在隔离执行期间关闭。受控传输结果明确标为受控证据，不能与真实结果混合。所有计划题保留在分母中，未知用量不记为零。报告按当前生产解析口径比较意图标签，不能代替严格输出结构、知识检索或完整业务验收。

该台账只保护本执行入口，不是产品级费用限额，也不统计用户在网页另发的对话。它能检测缺文件、坏链及仅截断journal的情况，不能抵抗管理员将整个目录连claim一起回滚；旧证据与授权仍需独立保留。

### 意图验证集的独立执行准备

[验证执行工具](backend/evaluation/intent_validation.py)固定使用原36道验证题及原顺序，不修改题目、标签、提示、模型参数或融合权重。每题仍共享一次LLM观察，分别计算仅LLM与三路融合；每类3题，最多36次物理请求。准备与受控测试不代表真实模型成绩。

```sh
cd backend
.venv/bin/python -B -m evaluation.intent_validation prepare \
  --offline-manifest data/benchmarks/preparation-v1/manifest.json
.venv/bin/python -B -m evaluation.intent_validation verify
.venv/bin/python -B -m evaluation.intent_validation status
.venv/bin/python -B -m evaluation.intent_validation report
```

以上命令不发送模型请求。验证批次固定在`backend/data/benchmarks/intent-validation-v1/`，准备时授权0、调用0；`prepare`还会只读核验原24题批次已封存，并关联旧协议、台账及全部观察文件的哈希。旧文件不改写，旧24次额度不续用。只有取得验证批次的新授权并单独登记，`run`才能发送。准备阶段的0次记录保持原样；随后取得用户单独授权的执行结果见下节，不能将已用完额度再次续用。

[验证台账](backend/evaluation/validation_ledger.py)复用原台账的锁、发送前持久占额、不可覆盖操作及结果哈希检查，单独绑定36项身份，不放宽旧24次上限。每题最多一次；失败、已发送取消与不确定尝试占额，执行异常暂停，不自动重试或通过重建目录恢复额度。报告保留失败、未知和未执行项，共享用量只计一次；受控输出不能混入真实成绩。验证题虽未用于调参，但对编写者可见，且同一题仅测一次，仍不能视为独立盲测或总体准确率证明。

本次执行准备的定向离线回归共466项通过，覆盖题集与计分、两批台账／执行器、传输、意图识别及非思考参数；新增执行测试禁用网络，只用受控响应。没有修改业务流程，未重复前端构建。
